# 備山 · 介面設計稿預覽

設計・製作：**Winson Liu**

登山共乘與找隊友平台「備山」的開發前介面預覽站。「流程總覽」分頁把 43 張畫面
串成六條使用動線（新手上路／能力資料飛輪／團員找隊伍／領隊開團／乘客找車／司機接單），
其餘三個分頁照角色瀏覽全部畫面。點圖或流程節點可放大，支援鍵盤 ← → 連續翻看、Esc 關閉。

## 本地預覽

```bash
python3 -m http.server 8080
```

開 <http://localhost:8080>。

## 部署

單一 `index.html`，無框架、無建置流程。Zeabur、GitHub Pages、Netlify、Cloudflare Pages
等靜態主機都會自動辨識 `index.html` 為入口，把整個資料夾丟上去即可，push 就更新。

## 檔案結構

```
.
├── index.html          ← 整站（樣式、資料、互動全內含）
├── assets/<分類>/       ← 英數檔名複本，網站實際引用的就是這些
├── <中文資料夾>/         ← 原始設計稿，保留備查，網站不引用
└── README.md
```

`assets/` 用英數檔名是因為原始資料夾名含空格與 `·`，直接引用會在部分靜態主機上出現
URL 編碼問題。原始中文資料夾保留不動，兩邊內容相同。

## 增補設計稿

1. 圖複製進對應的 `assets/<分類>/`，接續現有編號。
2. 編 `index.html` 底部 `TABS` 陣列，在對應 `items` 插入一筆
   `{f:'檔名', c:'規格代號', t:'標題', d:'一句用途', b:'徽章（選填）'}`。
   流水號與燈箱順序會自動重算。
3. 若新圖比該節現有最短的圖還短，順手調一下該節的 `ratio`。
4. **注意**：`FLOWS` 流程資料用「全域流水號」引用畫面。新圖接在節尾端不影響前面的
   編號；若插進中間，後面的流水號全部位移，要同步檢查 `FLOWS` 裡的數字。

## 流程總覽

`index.html` 的 `FLOWS` 陣列定義六條流程，每條是一串由上而下的 `blocks`（敘事式版面）：

| block | 用途 |
|---|---|
| `{k:'stage', n:'STAGE 1', t:'…'}` | 階段標題 |
| `{k:'entries', items:[{t,d}…]}` | 入口文字卡（沒有畫面的進入方式） |
| `{k:'bar', t, d, tone?}` | ◆ 判斷／匯流橫幅；`tone:'warn'`＝條件段（僅某些路線走） |
| `{k:'split', cols:[{tone,tag,chain,d}…]}` | 並排狀態容器，邊框色＝路徑色（`ok` 綠／`warn` 橘／`dashed` 虛線） |
| `{k:'steps', chain, labels?}` | 步驟鏈；`labels:true` 每步掛 STEP n 標籤 |
| `{k:'note', d}` | ※ 尾註 |

`chain` 裡的數字＝全域流水號（點擊開燈箱跳到該圖），`{t:'…'}`＝沒有對應畫面的抽象步驟
（出發、發布…）。路徑色圖例定義在流程分頁頂部。43 張中有 42 張被流程引用，
唯一例外是元件庫（43），它是規格板不屬於任何動線。

### 關於 ratio

縮圖框用 `aspect-ratio` 撐出等高卡片，圖以 `object-fit: cover` 頂部對齊。
每節的 `ratio`（高/寬）取自該節最短的那張圖、收斂在 1.5–2.2 之間，再 **+0.10**——
這樣節內最短的圖完整顯示，較長的圖顯示頂部一段，卡片等高、標籤對齊、沒有左右留白。
超過 1800px 的長圖另掛「長圖」徽章，點開燈箱看全長。

圖片在框內四周留邊（`inset: 16px 12px 12px`）：上緣是為了讓設計稿自己印在左上角的
代號標籤（`M-01-1c 隱私與揭露設定` 這種）不被卡片的 18px 圓角切到、有呼吸空間；
下緣是為了讓介面被裁切處與底下的說明文字之間有留白，不互相擠壓。
`ratio` 的 +0.10 就是在補回這 28px 留邊吃掉的高度，讓實際看得到的介面份量與留邊前一致。

## 徽章

- **規格** — 不是單一 App 畫面，而是規格集錦（三種身分動作列、篩選條件庫、空狀態六種、元件庫）。
- **長圖** — 原圖高度超過 1800px，縮圖只顯示頂部。
